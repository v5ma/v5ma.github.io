# Religious development and the nature-and-meaning bridge

The supplement contains 15 static HTML pages: an entrance, 12 studies and two evidence records. The September 9 continuation adds six studies and bridge-evidence.html. It preserves the author's explicit reconciliation proposal instead of treating pasted AI commentary as his own argument. The old sources.json is retained; bridge-sources.json adds the new page and source records, selected exact author statements and unfinished research.

The HTML files are canonical editorial source, not outputs of the principal Theology build. Edit them directly, update the appropriate manifest and run `python theology-wiki/religious-development/test_pages.py`. Add `--browser` for desktop/mobile HTTP checks. Add `--public-base https://v5ma.github.io/theology-wiki/religious-development/ --browser` to compare hosted bytes and exercise the public pages. Output goes to theology-bridge-test-output; tests never modify content or original archives.

The main theology-wiki/index.html entrance link leads here. The local supplement entrance lists every page. Existing principal reader indices, global search, narration, original conversation bytes, existing principal article bodies, shared roadmap/workbook, shared shell and sibling projects are not changed. These new studies are not claimed as principal-reader indexed or narrated content.

Source scope is explicit. The fourteen-book comparison examines one selected textual unit per previously named Tanakh book, not fourteen proven pre-exilic or Iranian-free books. The DNA study is represented only at authors' abstract and institutional metadata scope. Political inner beliefs, private observance and Jung/Campbell/film influences are not invented. The computational-God and prayer arguments remain constructive theology, not reported experiments. The full Treatise on Resurrection remains a primary-text follow-up.

The read-only GitHub workflow runs static tests, browser checks and, after a master push, public-byte and public-browser verification. Public checks may retry while Pages is deploying. The workflow does not commit files, rewrite the parent site, change Pages settings, or grant content-write permission. Passing tests establishes bounded structure and publication properties, not truth of religious or historical conclusions.
