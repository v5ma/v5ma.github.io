## Equivalent-observer audit and checks

The historical `ordinary_observer` and `learned_query` use one learner with
Euclidean distance versus squared distance. Both select maximum separation;
both admit a prototype iff its distance is <= epsilon+tolerance. Squaring
nonnegative quantities preserves these comparisons in exact arithmetic. Their
equality is therefore an algebraic-equivalence/implementation check, not an
independently specified benchmark policy. Check the stored paired decisions,
queries, gains and movement commands; do not rename the separate output-history
observer from the earlier application.

Checks include source identities; binary64 round trips; direct scalar versus
matrix responses; exact kernel relations; all fixed sensitivity rows; norm
matching; actual versus undelivered samples; original 96 outcome replay; and
the two mathematical witness classes. No floating-point rank estimate is used
to choose a contrast. Unexpected results remain visible and fail the relevant
assertion rather than trigger retuning.

Execution is one foreground process, below-normal priority on Windows, one
BLAS thread, fixed small matrices only. Output requires a new `results-v1`
directory and refuses replacement. No network, training, subprocess, scanning,
PDF build, provider operation, or source mutation occurs.
