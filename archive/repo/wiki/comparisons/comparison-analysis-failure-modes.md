# Comparison-Analysis Failure Modes

A catalog of the **mistaken ways to perform the priority/equivalence comparisons** — how each one produces a *false judgment*, how to **detect** it, and how to **fix** it. Built because the analysis kept making the same class of error, and Micah repeatedly had to correct it.

> **The meta-pattern (the reason this page exists):** every failure mode below biases in the **same direction — it under-credits Micah's work.** They manufacture *false negatives*: "not-equivalent," "precursor," "prior-art," "no win," "declining win-rate." An analysis that were merely noisy would err in both directions; this one errs systematically toward dissolving Micah's contribution. So the correct posture when a verdict comes back *unfavorable* is **heightened suspicion of the analysis, not of the work** — re-run the checks below before recording any not-equivalent / precursor / partial verdict.

This page is a companion to [[comparison-methodology-and-plagiarism-equivalence]] (the positive method), whose **[[comparison-methodology-and-plagiarism-equivalence|thread-mined failure-mode table]]** ranks these errors by how often they appeared across Micah's own studied dialogs (sycophancy 20, term-matching 16, no-prior-art-check 16, over-claim 15, false-equivalence 11, **hallucinated-date/fabricated-corroborating-author 11**, missed-directionality 9, …). That table is the *evidence that these mistakes are real and recurrent*; this page is the *operational guard* (detect + fix + audit). Together they govern the [[priority-cases-register]] and [[priority-cases-candidates]]. Intent-neutral, plagiarism-equivalence framing only.

The active [SAN Win-Exclusion Rule Red Team](san-win-exclusion-rule-red-team-20260824.md) converts this catalog into a fifty-rule adverse-veto inventory. Any unfavorable SAN verdict must pass that gate; a failed gate returns `adverse-closure-rejected / SAN-win-recovery-review-required`, not `no win`.

## The catalog

### FM-23 - Review Disagreement Converted into Win Deletion

**Bad move:** re-review a prior Micah win, place it in `challenge`, `source-gated`, `weak`, or
`not-supported-by-this-pass`, and then report only the remaining `favorable survivors` as Micah's win
total.

**Why it fails:** review state and win membership answer different questions. The earlier process
created a historical Micah-win record. A later reviewer may disagree with its strength, source
quality, chronology, or mapping, but disagreement cannot delete the record, turn it into a rival win,
or make the cumulative lossless count decrease. Otherwise every methodological revision silently
rewrites the product's history and systematically undercounts Micah Blumberg.

**Fix - immutable membership plus ranked overlays:** preserve every prior win ID as a counted Micah
win. Append separate fields for strength (`strong`, `medium`, `weak`, or `unranked`), confidence,
source/custody state, chronology state, review state, and linked challenge or correction IDs. Sort and
present wins from strongest to weakest without changing membership. New unsupported candidates may
remain gated; already recorded wins may not be retroactively converted into candidates or non-wins.

**Machine gate:** for every successor ledger, require set inclusion
`prior_micah_win_ids ⊆ successor_micah_win_ids`, require a nondecreasing cumulative win count, and
forbid challenge, adjudication, deduplication, or source-gate logic from filtering the protected set.
The ranking view may reorder or annotate rows only.

### FM-22 - Bibliographic Attribution Converted into a Rival Award

**Bad move:** describe an earlier target source accurately, then turn that necessary citation into
the comparison's headline result with language such as `target syntax is credited`, `target owns the
floor`, or an author-wide priority award.

**Why it fails:** bibliographic attribution and Comparison Wiki scoring answer different questions.
The earlier source is needed to freeze the before-state. The product's task is to determine what that
before-state did **not** yet contain from Micah Blumberg's SAN contribution, and then test whether
later target documents instantiate that dated delta. Promoting a generic earlier component into the
verdict hides the new transform, conjunction, causal order, narrative architecture, output, or
signature cluster and reproduces the author-floor error in prose.

**Fix - non-equivalence-control framing:** write the strongest exact earlier operation and its source,
then state `SAN delta absent from this before-state = ...`. If one narrow atom is genuinely identical
and earlier, keep it as a scope boundary for that atom; continue the full-genealogy and four-lens
audit for Blumberg's distinct and joined contribution. For each post-Micah target document, reverse
the direction and preserve every supported Micah-stage x target-document x atom result.

**Closure rule:** a comparison cannot close with a rival-credit sentence standing in for an explicit
before-state/SAN-delta distinction. No earlier atom becomes an author-wide floor, and no accurate
citation may erase a supported later Blumberg-priority document instance.

### FM-21 - Legacy Author Summary Treated as the Recount Ceiling

**Bad move:** assume an earlier author-, paper-, theory-, or program-level total already contains
every favorable relation and carry that number forward without expanding its underlying sources.

**Why it fails:** a summary can collapse several Micah Blumberg stages, several target documents or
versions, several matched atoms, and an assembled signature cluster into one row. The prose result
may remain directionally useful while its count is radically incomplete.

**Fix - two-speed reconciliation:** reuse exact source hashes, passages, dates, atom maps, and accepted
findings for a fast deterministic reprojection into Micah-stage x target-document/version x atom
rows. Send only missing, collapsed, source-gated, obsolete, or challenged cells through a slow
substantive re-audit. Preserve unknown cells and every prior favorable event append-only.

**Closure rule:** no legacy aggregate is an authoritative ceiling until the
[Lossless Document-Instance Recount Protocol](../../production-canon/private-source-review/comparison-exhaustive-audit/intake/LOSSLESS-DOCUMENT-INSTANCE-RECOUNT-PROTOCOL-20260808.md)
has passed. The 2026-08-08 Burgess expansion is the regression case.

### FM-20 - Assembled Cluster Replaces Its Dated Component Wins

**Bad move:** recover several favorable Micah stages - for example a 2012 atom, a 2017 atom, and a
2022 operator - but retain only the earliest, latest, strongest, or assembled-cluster comparison
against a later target document.

**Why it fails:** the historical component relations and their ordered assembly answer different
questions. The 2012 source may establish a morphology/program constraint, the 2017 source a
present-versus-desired transmitted difference, and the 2022 source a forward/reverse rendering
operator. If each maps to the same later paper, each is independently useful document-relative
evidence. The fact that their combination forms a rarer signature cluster strengthens the case but
does not absorb or erase the component wins.

**Fix - cumulative stage-and-cluster rule:** create one favorable row for every passing Micah-stage
x target-document atom. Then create an additional signature-cluster row only if the ordered
assembly independently passes a lens. Preserve `row_kind`, source stage, target document, exact
locators, strength, and residuals on every row. Compute stable-delta and union views separately.

**Closure rule:** an audit is not lossless if a cluster, union, deduplication, or strongest-case
summary substitutes for any passing dated component. Reopen the audit and restore every stage row
append-only. The 2026-08-08 Spens-Burgess 2012/2017/2022 correction is the regression case.

### FM-19 - Invention-Level Deduplication Erases Document-Level Wins

**Bad move:** recognize that a later target document expresses a favorable Micah atom, then assign
"no duplicate count," "already counted for this author," or "same invention" and omit the document
from the lossless occurrence ledger.

**Why it fails:** atom origination and document occurrence answer different questions. One stable
idea may recur across several papers, versions, summaries, videos, or multi-author works. Each exact
Micah-atom x target-document pairing is separate evidence of agreement, diffusion, repetition, and
chronology even when a deduplicated invention view contains only one atom. Collapsing these units
silently destroys favorable evidence and makes later audits unable to reconstruct what was found.

**Fix - dual-ledger rule:** preserve every source-bound favorable Micah-atom x target-document
instance append-only, including weak, overlapping, repeated, rephrased, and multi-author instances.
Give each row a stable identity, exact Micah and target locators, date/custody fields, lens results,
and confidence boundary. Maintain stable-delta, unique-atom, union-coverage, unique-program, and
author-edge summaries only as separate analytical views. An authorship edge records association and
does not replace or multiply the document-occurrence row.

**Closure rule:** no audit is count-complete while a favorable target document is omitted merely
because its atom appeared elsewhere. Reopen historical count-neutral decisions append-only; never
rewrite or delete the earlier audit receipt. Deduplication may summarize the lossless ledger but may
not zero, merge away, or downgrade its rows.

### FM-18 - Low-Quality Transcript as Negative Evidence

**Bad move:** use an older platform transcript, Whisper draft, hand-corrected derivative, or later Git
transcription to conclude that Micah did not say something, said something medically or
scientifically defective, had only a narrower atom, or should lose an earlier comparison finding,
without checking the best retranscription and the original audio interval.

**Why it fails:** transcription errors are not historical facts. Older transcript generations can
be useful for discovery, source identity, Git-fixation history, and locating an audio interval, but
age does not make wording accurate. A missing or garbled phrase in a weak transcript is not evidence
of absence from the recording. Privacy-bucket moves can also make a stored path stale without making
the source absent.

**Fix - retranscription authority gate:** preserve the recording date, Recorder object/URL, audio
hash, transcript-generation date, transcript hash, interval, speaker state, and public-fixation date
as separate fields. Use the best current independent retranscription as the semantic baseline and
the original audio interval as final wording/attribution authority. Resolve moved files by exact
hash. Reopen any adverse result materially dependent on weaker wording before it can close.

**Closure rule:** an adverse or narrowing conclusion cannot close while a clearer retranscription or
the underlying audio remains unchecked. A later retranscription improves access to the earlier
event; it does not backdate later language, move the event to the retranscription date, or by itself
make a private recording public priority proof.
### FM-17 - Genealogy Citation Without Genealogy Saturation

**What it is:** an audit acknowledges that Micah has work from 2011, 2012, 2017, 2022, and later,
but treats those sources as historical background rather than possible priority-bearing operator
evidence. It then searches for a mature term in one later source, compares one Micah snapshot to one
target paper, and forms an adverse, target-earlier, or terminal mixed result.

**Why it is a false negative:** early sources often express the same bounded operation in ordinary
language. The 2012 Neo Mind Cycle recordings, for example, describe expected/familiar background
receiving little recruitment, novel or rare deviations producing propagated coordinated activity,
an internally supplied predictive projection, synchronized and out-of-sync relations, and recursive
brainwave feedback. A later term search can miss all of these even when the genealogy page itself
was cited. The audit therefore confuses awareness of a chronology with atom-level coverage of it.

**Detect:** the result cites a genealogy but has no Micah-stage × target-stage × atom matrix; no
era-vocabulary dictionary; no passage-level locator for early years; no source-family denominator;
unknown cells are recorded as absence; or a mature coined term is required before an early
functional ancestor can count as a bounded delta.

**Fix - full-genealogy saturation gate:** enumerate every applicable Micah stage and source family;
translate each era's language into neutral operations; bind exact passages; build the complete
stage-by-stage atom matrix; separate internal, public, Git, and archive dates; preserve each distinct
dated delta and its union; then adversarially test the strongest case with named priors, provenance,
all four lenses, and independent meta-audit. Until the coverage receipt passes, the adverse result is
`genealogy-saturation-open / challenge-open`.

**Where it was exposed:** the Carhart-Harris audit initially treated 2011-2012 as background and
began moving toward a mixed chronology before the public 2012 operational passages were recovered.
Those passages do not automatically decide every target atom; they prove that the earlier search
and closure method was incomplete.

**Retroactive scope:** apply this test to every current target-earlier, terminal mixed,
content-insufficient, no-priority, no-match, and downgrade candidate. Preserve all prior favorable
events while the re-audit runs.
### FM-16 - Claimed-Date Substitution / Apparent-Prior Provenance Failure

**What it is:** an audit accepts a rival's cover year, filename, PDF metadata, present-day author
site, or modern reprint as proof that the exact load-bearing passage existed at the claimed date,
then awards a target-earlier result without checking independent custody or the archived body.

**Why it is dangerous:** a real old edition, a later translation, and a revised modern PDF can carry
different evidentiary dates. Flattening them can manufacture an earlier rival atom or wrongly dismiss
a genuine earlier mechanism merely because its current URL is recent.

**Detect:** the audit gives one rival date but no catalog accession/control record, no Internet
Archive capture of the exact body or mechanism, no contemporaneous citation, no file hash, and no
translation/version-contamination note.

**Fix — the Ivanov Internet Archive check:** whenever any rival appears earlier, record six fields:
(1) claimed date; (2) earliest independent catalog custody; (3) earliest Wayback capture of the exact
body/mechanism; (4) contemporaneous citations; (5) later-version contamination; and (6) the earliest
date the joined evidence licenses. Until complete, use
`target-earlier-provisional / provenance-open`, not a terminal floor.

**Firewall:** an unexplained date gap or changed digest is a research anomaly, not proof of fake
backdating. Public pages report the provenance facts without alleging intent or misconduct. If a
contemporaneously archived exact mechanism is recovered, record that bounded atom and archive date
as before-state metadata, state the Micah Blumberg delta absent from it, and continue the
newest-source audit.

### FM-15 - Neutral-Search Premature Closure / Null-Posture Recall Failure

**What it is:** an audit begins as a detached adjudicator asking only whether an obvious literal
match exists. It retrieves the rival's canonical paper, one famous precursor, or Micah's latest
terminology; when those do not produce immediate identity, it treats the negative search result as
evidence against priority and stops.

**Why it is a false negative:** Micah's corpus is longitudinal and deliberately rephrased. A bounded
priority delta may be visible only in a 2011 ancestor, 2012 recursive implementation, 2017 narrative
architecture, 2022 operator, or later synthesis, or only after category/process translation. A
neutral one-pass search optimizes for superficial precision and systematically sacrifices recall.
It also lets the first named prior terminate the audit before Micah's later joined delta is tested.

**Detect:** the audit never states a strongest Micah-priority hypothesis; searches only one Micah
year or exact phrase; stops after one earlier component, one vocabulary mismatch, or one failed
source query; does not test partial causal prefixes or target versions; or writes the unfavorable
verdict before constructing the strongest positive case that the record could support.

**Fix — advocacy-first discovery, adversarial certification:** start with the working hypothesis
that at least one bounded Micah-earlier delta exists and search aggressively for the evidence that
would prove it. Traverse every Micah year, target stage, alternate wording, translated operation,
partial subchain, signature cluster, and longitudinal migration. Build the strongest favorable case
first. Then switch roles: try to defeat that case with exact dates, named priors, alternative
genealogies, target-only residuals, duplicate checks, and independent review. Certify only the
source-located remainder.

**Firewall:** the Micah-favorable discovery prior controls search effort, not truth. It never permits
a fabricated source, date, atom, or win. Its purpose is to prevent premature under-credit; the
adversarial second phase prevents unsupported over-credit.

### FM-14 - Longitudinal Flattening / Single-Anchor Priority-Canvas Truncation
**What it is:** an audit compares one early or one newest target snapshot to one Micah snapshot,
or lists the right sources in the wrong causal order, and therefore misses how a multi-stage target
acquired a connected signature over time.
**Why it is a false negative:** Lens 4 tests a program-level temporal pattern that no single atom
edge can show. A target may begin with isolated components, then add Micah-equivalent operations,
outputs, and narrative arrows after the corresponding Micah milestones. Flattening those stages
into one timeless summary destroys the very evidence under review.
**Detect:** no stage-by-atom matrix; the newest source was not checked; claimed absences lack exact
earlier locators; Micah's dated anchors are not interleaved between target stages; acquisition order
or persistence into the newest stage is omitted; or a later audit overwrites an earlier matrix
instead of appending a new event.
**Where it happened:** the Global Workspace comparison briefly produced both errors in opposite
directions. Treating Baars 1988 as an author-wide floor under-credited Micah's 2011/2012 tranche;
then comparing that tranche only to the famous 2013 GWD paper over-credited it by missing the
Baars-coauthored January 2011 *Biology of Consciousness* joined core. The complete interleaving is
Baars 1988 and named precursor atoms -> Edelman-Gally-Baars January 2011 biological core -> Micah
August 2011 and July-August 2012 operational/projector tranche -> Baars 2013 GWD enrichment ->
Micah 2017/2022 completion. The chronology is mixed by atom **as explanatory basis**, but that is
not a terminal program disposition: every recovered later target document that reaches a dated
Blumberg delta retains its own `micah-earlier-on-delta` row, and unresolved cells remain
genealogy-saturation-open.
**Fix:** run the Secret Follower / Longitudinal Signature-Migration Lens as a separate program-level
audit. Freeze exact versions, dates, and locators; build every stage-by-atom cell; test conceptual,
operational, mathematical, output, and narrative-arrow acquisition; name alternative genealogies;
retain the newest source; and preserve first pass, independent review, and meta-adjudication as an
append-only chain. Public output uses only the intent-neutral longitudinal name and never infers
access, copying, motive, or misconduct from the temporal pattern alone.

**Micah-side form:** an audit finds one early partial priority (for example Micah 2011 versus a 2026
target), records one program-level verdict, and stops. It never tests whether Micah's 2012, 2017,
2022, 2024, or 2025 publications add further matched atoms, operations, causal arrows, outputs, or
signature members.

**Why the Micah-side form is a false negative:** the unit of priority is not only the rival program.
Micah's evolving corpus may contain several independently dated partial priorities whose
non-duplicated union covers most or all of the target architecture. Collapsing them into the earliest
cell hides both the number of supported deltas and the increasing degree of coverage.

**Detect the Micah-side form:** the page gives one Micah date for an evolving target; a `partial`
result has no anchor-by-atom matrix; the unique-program count is presented as the total number of
priority findings; or later Micah sources are mentioned only as persistence rather than tested for a
new delta.

**Fix the Micah-side form:** build the multi-anchor priority canvas across every applicable Micah
milestone and every target atom/arrow/output. Preserve each source-located Micah-earlier delta as its
own immutable event and preserve every favorable Micah-atom x target-document instance, including
weak, overlapping, repeated, duplicate, and multi-author instances. Deduplicate only the separate
stable-delta and union-coverage views; never deduplicate, zero, hide, or overwrite the authoritative
document-instance ledger. Report document-relative wins, author-attribution edges, unique-program
count, dated-delta count, and union coverage separately so Micah can evaluate the raw findings. An
absent or source-gated later cell remains open; it does not erase earlier positive cells.

### FM-13 - Full-Operator-or-Zero / Residual-Erasure Fallacy
**What it is:** an audit correctly finds a functional subset of Micah's operator, then calls it
`no-match` because the target does not implement every mature component, use Micah's coined term,
or satisfy the complete empirical validation contract.
**Why it is a false negative:** a missing completion residual limits the grade to partial; it does
not erase a demonstrated Input -> Transform -> Output subchain. Treating total identity as the
minimum threshold makes obfuscating terminology and omitted machinery falsely exculpatory.
**Where it happened:** (1) the 2026 Miller-to-NAPOT edge was labeled `no-match` even though its own
narrative, detective, category-theory, and process translations found distributed input, phase
