# Field Desk / Neighborhood Missions v0.16.1

This is a focused playtest usability update to the full unified game, not another replacement demo. All eight spatial modes, original-city and Lantern Ward gameplay, stable IDs and independent reward ledgers remain. No private hub implementation, cross-game walking portal, sphere link or A-Frame migration is included.

In XR, Y / the available application-menu control or the existing raised-pinch gesture summons a low, world-fixed field desk. Its round pedestal and panel rise from near floor level. Page changes and head tilt do not reposition it. Resume immediately hides the large desk and long rays. Controls offers desk height, distance, scale, instant opening for reduced motion and Place desk here. These settings live only in svgn.neighborhood-field-desk.v1; unreadable/future data is retained rather than overwritten. The runtime uses the platform local-floor pose when available and an explicitly estimated floor otherwise; this is not room scanning or obstacle detection.

A compact mission map, goal, distance/floor hint and riding-control caption are drawn into a texture on a 3D wrist panel inside the game canvas. It follows the non-dominant tracked grip or hand wrist rather than the headset. A near-feet placement and Hidden option are available. The original-city map uses a local tangent projection and an edge marker for distant current objectives. Lantern Ward uses its real mission-aware map. Current target and progress are read, never fabricated by the HUD.

Vehicle speed defaults to physical left trigger, with physical right trigger braking. Right grip interacts, A hops and B mounts/docks in the default right-handed Action profile; Y opens Menu. Controls offers right-trigger speed or retention of the prior Action/Courier profile. On-foot trigger aiming, tools and combat are unchanged. A compact context caption distinguishes riding from on foot. Existing handedness and stick-swap preferences are not rewritten. Release speed still uses the existing game's braking logic.

The XR menus retain their existing game actions and save confirmations. Ray intersections have a visible dot and highlighted button region. Desktop/phone still use their existing accessible DOM menus and HUD: a complete screen-play in-canvas migration is not claimed. Neither the standalone recovery district renderer nor the frozen legacy entry is replaced.

Evidence: all 315 inherited model/input tests plus 11 new field-desk tests pass locally. Initial unit failure was a strict binary floating-point equality for 1.1 + 0.06; the geometric check now uses 1e-12 and retains the same expected position. Local browser navigation is blocked by ERR_BLOCKED_BY_ADMINISTRATOR, not passed. The focused field-desk browser test drives real WebGL with synthetic Quest inputs, never changes actor/mission state, and writes an incremental result after each check. Source and public results are separate. Check the external release receipt for actual completed outcomes. Hardware comfort, readability, controller/hand tracking and user approval remain open.

Rollback uses a new scoped revert commit, never a reset of shared master. Keep old progress and the private/public boundary. Next: improve reachable objective cues and evaluate the wrist placement and font size in actual Quest play; then migrate screen-play chrome without losing accessible text-entry and recovery.
