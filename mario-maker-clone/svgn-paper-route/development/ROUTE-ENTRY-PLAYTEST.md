# Route Entry: focused physical playtest

This is a test protocol, not a record of completed hardware testing. Consult verification/route-entry-0.27.json for the current exact source and publication state. Do not infer that a prepared branch is live.

## Entry and understanding

On the published v0.27 release, open the ordinary route catalogue. Without using the small header XR control first, identify Sunrise Borough and choose its AR or VR action. Confirm that the displayed route name and presentation match that choice. Screen is an explicit 2D choice; the original large card retains Play in current view. A last-used-mode hint must not request immersion automatically.

Repeat with Waterwheel Boulevard and an advanced route after exposing the advanced catalogue. Look for missing cards, duplicated controls, horizontal overflow, ambiguous names or mode buttons that appear to belong to another route. The original chapter IDs, authored routes and earned records must remain stable.

## Native controls

After entry, ride using the familiar controls, then pause, open Sound, change one setting, go back, resume and exit XR. Test both controller-ray selection and stick/grip navigation without aiming a ray. Menu A/X confirm and B/Y back must not replace jump, boost, paper or whip while riding. The last-input readout is diagnostic feedback, not telemetry. Record the build, session mode, actual controller profile if available, selected target and whether that readout changes for any failed action.

Controller riding should have no persistent menu slab. Turning or leaning should change the view naturally, not rotate the game, move its aperture or place a flat occluder through the route. Repeat with hand input; optical hand tracking and physical controllers are separate observations.

## Cancellation and switching

From an existing route, select another route in the same immersive mode. It should use the current session. Select the other immersive mode, cancel, and confirm that the original route and session remain. Confirm a mode switch: the old session should end cleanly, and the new mode should require a fresh deliberate entry. Do not call a browser-owned permission screen a game menu.

Refuse immersive permission. The requested new chapter must not start, and the game must not silently substitute Screen. Cancel a delayed request and check that a late approval does not unexpectedly start the new chapter. An unavailable mode should have a reachable explanation and an explicit Screen alternative. Keep pending capability checks distinct from unavailable results.

Selecting Screen from XR should end the immersive session and restore a usable browser and 2D game. Re-enter XR afterward. If WebGPU requires a WebGL page reload, the warning must say that the unfinished run ends; only saved progress and the selected-route intent survive that reload. Save or export unfinished Workshop work first. Never clear site data to update or recover.

## Save and presentation limits

Observe an existing medal, controller remap and saved Workshop document before and after the journey. Confirm that a last-used-mode hint persists where browser storage permits and is described as session-only when it cannot be written. A mode hint is not an award, chapter completion or automatic save migration.

Record what felt unclear or required unnecessary button presses, not only whether a test reached its final screen. This entry release does not claim to fix ground blocks, every low-ramp trap, advanced Bezier ergonomics, full XR chapter completion or headset performance. Keep those movement-first and physical-device gates open in the canonical roadmap. No private hub or new cross-game portal is part of this protocol.
