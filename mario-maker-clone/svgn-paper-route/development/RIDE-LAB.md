# Ride Lab: design the ride, not just the endpoints

Version 0.12 adds a Workshop rehearsal using private instances of the actual v0.11 two-face rail physics. It does not copy old one-sided assumptions from the unfinished authored-layout PR28. The first chapter layout is not silently replaced by that draft.

Select one open rail, choose a starting fraction, signed speed, side and held control, and rehearse a carried-state route. The same rider position and velocity continue through every sampled catch. A speed comparison is five separate, explicitly labeled scenarios, not an all-purpose reachability proof. Rehearsals stop on terrain; they do not model enemies, pickups, moving platforms, timed legacy-loop exits or automatic whip casting. Six declared nitro entry speeds traverse the corrected practice yard without the conservative deck warning, and the original blunt lip is retained in a regression fixture to prove that the warning can actually fire.

Worker computation receives a copy of the complete encoded document. Grip settings, collision callbacks and contact history are private. Editing invalidates the trace, starting a geometry gesture clears it, and cancellation terminates the old worker. Computation cannot move the real rider, consume real nitro, collect items, alter the document or write campaign medals. Exported traces include source document and assumptions. Large inputs and long scenarios are bounded.

Smooth join builds an actual contiguous cubic roadway between the closest compatible endpoints. It aligns bridge tangents with the incoming and outgoing rails, retains existing Bezier segments, and preserves independent handles. Too-distant endpoints, occupied terrain and crossing rails are rejected before the document changes. A join is one undo transaction. It is a construction tool, not proof that a bridge is comfortable to ride at every speed. The original straight join remains available.

The optional Flight guide (G) is disabled by default. It projects a short copied-state prediction through the real perspective camera. A rail rider sees a possible receiving contact; at a peg it shows an immediate-release scenario. It never steers, snaps, aims or relocates the rider. The same held input is assumed throughout the prediction. A route can invalidate it through steering, collisions, pickups or moving objects. It fails visibly and leaves normal gameplay functioning if the worker or document cannot be used.

This revision changes the practice yard's final receiving entry from [1910,1900] to [1760,1950], leaving the other control points and downstream exit unchanged. That produces a cleaner approach after the underside release. The existing 66 timing-variation fixtures remain, while a separate conservative circle/deck audit identifies the original lip as a warning. A diagnostic warning is not presented as a new physical collision rule. Normal rail grip/ride behavior is kept identical by wrapping the existing implementation in an isolated-instance factory; direct equivalence tests cover that refactor.

New modules attach through a small optional loader after the existing application starts. The complete original index and Workshop implementation are not rewritten. The default unicycle, bike option, independent Bezier controls, ground-first adventures, finish-only progression, instrumental music, saved drafts and legacy expert levels are preserved. No Supabase, account, payment, coupon, entitlement, multiplayer, Theology, Dino Atlas or Studio configuration is changed.

Acceptance must run native HTTP/3D editor and guide flows as well as the established rail/editor/ground/expert/whip regressions against exact committed source. Reports distinguish model seeds from real gameplay driven only by keys. Read-only CI records source identity and failure evidence. The existing publication workflow now verifies 18 owned runtime files, including every loader and worker dependency, rather than assuming a successful merge is a successful public release.

Outstanding design work: integrate and retune the authored chapter under two-sided grip; convert good route traces into discoverable cues and reward lines; widen expert whip reconnection windows; model controlled braking recipes and moving encounters; measure native GPU/phone performance. This tool release does not establish that every current optional branch is reachable or fun.

Primary technical references: https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers and https://developer.mozilla.org/en-US/docs/Web/API/Worker/postMessage . Inputs are copied rather than transferring the live document buffers. Rollback is a scoped merge revert, never clearing player drafts or resetting unrelated history.
