# Arrival windows and recoverable mistakes

A valid route needs more than one successful arrival state. The first native canal run in 34067294578 reached the correct fork exit but retained the brake for additional flight ticks and missed the collector. The geometry fixture reproduced this: five extra brake ticks were sufficient to miss the original mouth. The revised collector has a curved lower mouth reaching back into the arrival corridor. Its downstream exit remains unchanged. Simply extending a straight edge caught the independent road re-entry on the underside and broke that route, so that attempted solution was rejected.

The accepted mouth preserves the four complete carried-state recipes, 48 declared speed/entry-offset cases, the original braking-position sample, precision catches, and the 70-pixel distinct-centerline clearance. An additional 21 scenarios vary brake onset and post-lip brake duration from 0 to 12 ticks. These are explicit deterministic model cases, not a claim that arbitrary input succeeds. Native tests still require actual normal-key canal entry and a complete first-attempt finish. The later road entrance is also verified separately in native 3D so that fixing one route cannot silently break another.

An unchanged Hookline regression exposed a near-vertical late release at position (1409.308,1690.059) and velocity (-1.185,-25.973). The old recovery road began too far right to catch this attempt. A broad curved mouth now joins the original receiver at (1760,1840), preserving the long cradle and downstream launch at (3595,2065). The original release fixture fails against the old shape and catches both actual receiving sections against the revision. Forty finite rope-length/release-angle scenarios complement the real-key course replay. These are recoveries, not all high-retention racing lines: a poorly aligned impact can lose speed and require acceleration along the same physical surface.

No grip radius, collision tolerance, gravity, input timing, automatic steering, score gate or player teleport was introduced. The source and receiving roadway bodies are checked separately from the native contact function. The populated story-level ground route still finishes without any aerial requirement. Existing unfinished branch proofs and physical-device performance remain open work. Exact committed source, native video/screenshots and public-file hashes determine release status; model passes alone do not.
