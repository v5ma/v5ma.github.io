# Exact-source release process

A feature branch is not a release. The source-recovery operation for this repair is complete: all staged transport fragments were removed after baseline and final SHA-256 verification. The continuing acceptance workflow is read-only and does not prepare, patch, commit or push application code. This prevents another incomplete transfer from appearing to be a finished implementation.

The rail/editor workflow runs on relevant pull requests, this feature branch and manual dispatch. It checks module load order, the in-game version against release.json, absence of partial transfer directories, and the selected document/geometry/physics tests. Five independent native-browser jobs cover editor gestures and files, a top-to-underside-to-top ride, the road campaign, First Flight, and Hookline Run. Each report records the exact tested source and preserves screenshots, exceptions and video on failure as well as success. Tests use ordinary UI/key input; unit trajectory fixtures are separately labeled.

The first native run exposed an overly demanding overhead approach in the practice yard, unintended attachment from the grounded street, and an expert regression script that clicked controls behind the newer full-screen Workshop. The receiving rail was reshaped without moving its downstream exit, road attachment now requires leaving the ground first, and tests navigate through the Workshop's real Back/Playtest controls. The lesson has a separate 66-case carried-state speed/timing check. These changes do not weaken the native requirement to catch the top, underside and top in one uninterrupted real-input run.

The enlarged toolbar now wraps inside the viewport rather than stretching the canvas and clipping controls. The default electric-unicycle appearance, optional bike appearance, and forgiving/precise grip choices remain visible. Library and community entry points lead to existing code; this is not a replacement account system.

After a reviewed merge, the existing GitHub Pages publisher serves the site. A separate read-only publication workflow polls twelve owned runtime files and compares their SHA-256 digests with the merged source. It records the build, commit and each public response. Only that successful check establishes that the public link serves the release; merging alone does not. The in-game build indicator and Check update button help distinguish a stale tab from the current version. A requested reload warns about unsaved Workshop changes.

For later releases, update the runtime build and release.json together, run exact-source acceptance, review actual captures, merge the expected head and inspect the public-file proof. Never silently turn failed native replays into passing results by modifying player state or suppressing the failed check. Longer software-GPU time allowances must preserve the underlying assertion and be documented. Keep generated evidence outside the application source tree.

Theology, Dino Atlas, Studio, Supabase schema, paid accounts, coupon entitlements and multiplayer services are outside this repair. The pending authored-layout branch is not silently merged. Further native GPU, phone, browser and controller coverage remains necessary. Revert the scoped release commit for rollback; do not reset unrelated repository history or clear players' saved drafts.

Reference for the permission model: https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax . Checkout uses persist-credentials: false and acceptance/publication use contents: read. No workflow here requests a repository-write or account-service secret.
