# Cloudview: implementing the approved image inside the game

The user's approved visual target is a bright, premium-styled 3D sky delivery game: thick gold mechanical loops, directional lights, blue speed trails, floating rocky islands, greenery, waterfalls, a distant city and blimp, a detailed helmeted courier/bike, red mailbox destinations, cream envelopes and a compact blue/gold HUD. This change implements original procedural geometry and a state-bound HUD inside the actual Paper Delivery application. It does not generate another concept image, insert an illustration as a fake gameplay screen, or create a separate app.

New files: cloudview-assets.js (geometry kit and courier model), cloudview-world.js (world surfaces, scenery, targets and animations), cloudview-ui.js and cloudview.css (live HUD). The existing SkyVisual interface is implemented by Cloudview so the established WebGPURenderer and frame loop remain in use. The packaged Three.js distribution is unchanged. There are no remote runtime asset dependencies or new analytics, accounts, fees, AI services, or data migrations.

The gold plated decks follow the existing ordered rail points. The geometry uses merged batches to avoid one draw call per bolt or leaf. Waterfalls, distant rails, flowers, structures and the airship are scenery, not new collision paths. Red postal targets retain their existing game hit locations. Real collectibles disappear when the corresponding game cells are consumed. The new courier is a visual replacement in sky play; original characters/editor assets remain available in non-sky modes. Visual body extents do not redefine collision extents.

The sky-game.js change is confined to play camera framing/look-ahead. Loops, exit timing, launch velocity, ballistic motion, receiver catches, scoring, deliveries and route data are not changed. Camera zoom is not adaptive graphics quality. Rendering quality is fixed; reduced-motion preference suppresses decorative motion. The 2D fallback and full original editor are retained. Original packet meshes remain visible until a separately validated projectile replacement is provided.

Validation evidence comes from the Cloudview workflow artifacts. A preliminary render/playability check captures real screenshots and a normal-input lap/launch/delivery/catch. The existing full three-route input replay then checks completion, the lower detour, saved medals, pause and editor restoration. Test runners block external account services and start with audio muted. Software-rendered CI is not evidence of frame rate on physical mobile devices or native WebGPU hardware. The procedural implementation is an original interpretation of the reference, not a claim of identical hand-authored asset detail.

Technical references: https://threejs.org/docs/pages/WebGPURenderer.html and https://threejs.org/docs/pages/InstancedMesh.html . The actual deployed library version, not current documentation defaults, controls runtime behavior.
