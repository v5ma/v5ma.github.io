Vesperfall 0.14.0: The Returning Bell.

This release integrates the first authored replacement opening into the existing game. It is a playable development slice, not a finished campaign or an assertion of AAA quality. The earlier LEVEL-DESIGN-RESET.md remains the design brief; this file records the narrower implemented scope and continuation contract. Publication requires the matching source and live workflow receipts, not this document alone.

The new-player opening is now The Returning Bell. The refuge, bellcourt, west cloister, choir gallery, tower, lower ambulatory and service undercroft form one original place. The ordinary ground approach and longer upper approach reconnect at the tower. Existing arrow sweeps, movement collision, shield, Blink predictor and enemy behavior are authoritative. The archers do not magically climb stairs. Defeating every enemy is not required: restore the signal with an actual shot at the bell or an interaction beside it, then return and interact at the refuge.

A gallery winch raises and lowers a bank of screens. Lowered screens shield the ground crossing and block a forward-court firing line; raised screens expose that line. Both positions update the same solids used by projectiles, line of sight, movement and Blink. Closing onto an actor is refused. There is no water-level simulation, new patrol/investigation system or moving elevator in this chapter.

The service descent leads to the original refuge gate from inside. Its latch removes a genuine collision-backed barrier and connects the route beside the starting basin and pale statue. The open connection persists in that expedition. Recognizing the familiar landmarks is an intended player experience, not a measured result. All walking routes have real stairs and supported floors; valid optional Blink connections use the existing trajectory and landing rules.

The chapter completion awards the ordinary sector outcome once. The reward screen explicitly explains that choosing a blessing continues into the retained Endless mode. The next authored chapter is not built. First Bell lessons, Bellkeeper Oath, practice, trials, old Endless expeditions and stationary AR Sanctuary remain separate accessible choices. The default content is replaced, not the engine or every historical challenge mode.

Keep the exact IDs returning-bell-1 and hollow-dominions-1 immutable. A prior Surestep checkpoint fixture is retained at tests/fixtures/legacy-surestep-checkpoint.json. Old checkpoints still reconstruct the original generated geography. New checkpoints store bounded version-1 chapter flags. Restore applies gate and screen geometry before checking a saved position, then applies the existing finite-state, resource, identity, projectile and reward validation. Existing profile/storage keys and atomic save envelope remain unchanged. Do not clear localStorage or silently relocate an old saved player to implement future content changes.

Desktop and full-scale first-person VR share the same chapter. Xbox down D-pad selects Blink and left D-pad cycles usable damage arrows. Interaction uses the existing A/E or bow-hand lower face button. Menus and held-Y quiver navigation retain priority. Physical two-controller archery, handedness, cancellation, shield, weapon/reload and hand-pinch spatial menus remain in the existing input system. Bare-hand UI does not enable hand-only archery or locomotion.

AR Architect's Table is paused architectural inspection through an actual supported immersive-ar session. It shows only places discovered in the suspended expedition. A manually placed virtual stand supports layer selection and deliberate recentering. Controller rays/stick selection and thumb/index joint pinches operate its menus. The table is not a room scan, detected physical anchor, furniture-aware occlusion system, full-scale AR campaign or third-person playable diorama. Returning to the existing Sanctuary and exiting AR remain available; exiting restores the exact paused expedition. All AR activity remains unscored and cannot change expedition mechanisms or claim new discoveries.

The architectural renderer reuses the existing original procedural art and same-origin licensed stone materials. Floor geometry, stairs, cover, gate and screens are drawn from the chapter's authoritative layout. The new skyline tower, nave ribs, gallery, service roof, basin and statue provide distinct orientation cues. These remain low-poly development assets. Normal-map, shadow, readability and physical-device costs require separate review; visual decoration does not own collision. Legacy Tidelight water remains available in legacy modes but is excluded from the new chapter rather than painting unrelated pools over its corridors.

Four design descriptions live with the source. Physical: returning-bell-model.js defines the floors, solids, approaches and closed/open return graph. Conditional: the same model defines reversible screens, safe closure, service-side latch, signal and return outcome. Behavioral: five retained defenders have deliberate posts and existing committed attacks; no new general behavior system is claimed. Information: the sheltered arrival, named places, visible winch/screen relationship, familiar refuge landmarks, contextual HUD and discovery-limited atlas/table explain the connections without an omniscient map.

Software acceptance uses node --test vesperfall/tests/*.test.cjs, python vesperfall/tests/production-workbook.py and python scripts/check-vesperfall.py. The new model tests use actual collision movement over both approaches in every screen/gate state, real projectile signal activation, a predicted and executed gallery Blink, actor-safe closure, exactly-once reward, new save restoration and the original legacy checkpoint fixture. The Returning Bell browser journey exercises ordinary production WebGL through generated keyboard/Xbox/WebXR inputs, actual mechanisms, a saved elevated position, AR inspection and restoration, a real bell shot, service return, reload and completion. Tests must not set player coordinates, enemy health, unlocks or progression to bypass the journey.

Run the new browser journey with python vesperfall/tests/returning-bell-browser.py after starting the repository at port 4173. Retained Dominions, Surestep and Pilgrim suites explicitly select legacy content where that is the subject of their assertions. First Bell, Rosefire, Resonant and launch regressions must remain available. For publication, run tests/verify-live.py against the committed source and repeat the new journey with TEST_BASE_URL=https://v5ma.github.io. Record exact test counts from reports, not forecasts.

The canonical 76 tasks and six-sheet workbook advance together to 0.14.0. V52, V57 and the broader first-session/interface tasks remain Partial. V64 unfamiliar-player/replay research and all physical-device rows remain open. The next production task is to observe whether new players can plan, recognize the screen tradeoff and return connection, then exploit their knowledge on replay. Tune the complete opening before expanding the campaign. Physical Quest seated/standing reach, full-scale VR bow clearance, AR legibility and hand occlusion, Xbox reconnect/suspend, sustained frame time, human art and listening review are not certified by emulation.

Rollback is a new scoped revert of the source, release and workbook together, retaining all concurrent sibling changes. Do not remove support for returning-bell-1 saves merely to roll back artwork; retain or explicitly handle the new layout identity. Never reset master or delete player progress.

Design basis: the user's September 15 place-mastery source and the approved LEVEL-DESIGN-RESET.md. No commercial maps, meshes or private story content were imported. Native WebXR session/hand semantics follow the W3C WebXR AR and Hand Input modules; physical-device behavior still needs observation.
