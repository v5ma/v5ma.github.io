# First Steps: browser lesson design

Version 0.6.0 follows production task A-06. The entry card is beside the input selector, before session/practice settings. Choose mouse/touch slices, D/F/J/K keyboard timing or LT/LB/RB/RT controller timing, then choose Learn to play. No forced introduction, dismissal dialog, account or cloud service is added.

Meet your hands requires three of four connections and at least one from each hand group. Find the beat requires four of six. Follow the arrows requires four of six using unchanged directional rules in slicing mode; timing modes explicitly learn a short phrase without arrow grading. Pause with confidence requires two connections from both groups plus deliberate Pause and Resume. Window focus changes, renderer stalls and controller disconnects cannot satisfy that pause requirement. Failed exercises repeat; passed exercises can be retried or advanced at the player's pace. The exercises use fixed comfortable-spacing candidates, not hardware-validated reach claims.

Each exercise has a short, original generated stereo pulse soundtrack at 104 BPM and a four-beat count-in. It is a temporary buffer in the existing single-source transport, not a replacement or modification of any catalog soundtrack. It follows music volume and mute. Normal collision windows, blade-speed guards, score equations and interruption behavior are not relaxed for teaching. The visible lesson UI emphasizes connections and goals rather than the internal score.

The only new saved data is `prism-current.v1.lessons`, containing schema version 1 and a deduplicated list of recognized completed input modes. Nothing is written until all four exercises pass in sequence. Full-song and Practice Lab writers are bypassed for lesson charts. A change of input resets the sequence. Exiting clears partial progress and the temporary lesson audio. A saved completion does not skip or force a lesson on a future visit; the card simply acknowledges it.

Automated acceptance covers bounded chart/PCM generation, wrong-direction rejection, actual core hits, both-hand and pause-proof requirements, malformed completion data, cancellation and score-writer isolation. The native browser suite uses the production renderer/audio and emulated standard-pad input for a failed attempt and full curriculum, then checks keyboard and pointer inputs, save isolation, reload and original-song return. It never assigns scores, note judgments or the song clock. Existing game tests run alongside it. Native screenshot and workflow receipts must be consulted for actual results; a test procedure is not a passed test.

A-06 human acceptance is still open. Observe five new players without coaching, including real touch users, record where they struggle, and revise instructions and pacing. Physical Xbox/Quest testing, in-headset teaching, color/contrast review across vision differences and sustained device performance are separate gates. Reduced-buffer software rendering verifies behavior, not consumer frame rate or comfort. Browser sound permissions may require one genuine tap or keypress.
