# XR menu recovery / 0.10.1

The owner reported that neither ray selection nor controller buttons/sticks could start a battle in AR. This reopens RV-04 and RV-06 from the active production board. The baseline is master 8b709a023660f8c8df6f1485eb487a8dea75ea85. Its Prism files are unchanged from the 0.10.0 release.

The Start handler called session.inputSources.filter. Real WebXR exposes a live XRInputSourceArray, which is iterable/indexed but does not provide Array.filter. The earlier emulator used a normal Array and therefore missed this device-specific failure. The old UI also used separately positioned invisible targets instead of the displayed button rectangles, did not show ray hover, and did not implement XR thumbstick navigation. The prior browser pass did not establish that this UI worked on the owner's Quest.

The bounded repair converts source collections explicitly, uses the rendered panel mesh's actual ray intersection UV to identify the painted button, and uses one shared rectangle layout for drawing and picking. The ray ends at a visible cursor; hover and keyboard-style controller focus are highlighted. World matrices include the panel's ancestors, and moving line buffers cannot disappear because of stale frustum bounds. Menus continue receiving input when grip tracking is unavailable; only combat requires both valid controller poses.

Point plus trigger selects a highlighted button. Either thumbstick navigates; A/X confirms the selected option without needing a ray. B/Y directly starts or resumes from a menu and pauses during combat. Native selectstart/selectend and polled triggers share a latch so one press cannot execute twice. A trigger used to resume must be released before it can fire in combat. Reopening the menu places it in front of the current view without moving the gameplay stage or camera. Hand-pinch menu interaction remains available. No permanent floating menu is added during play.

Hypothesis: matching the real device collection and rendered target coordinates, with a direct non-ray fallback, removes the blocked-start failure. The primary observation is starting and resuming both chapters through AR and VR menu input after a translated, yawed, seated initial pose. Tests include all visible button centers/corners, differing aim/grip orientations, native events, combined event/polled input, one-controller menus, missing grip poses, visibility recovery, recentering, and saved-data preservation.

The new strict emulator intentionally does not have .filter, .find or .map on inputSources. The negative reproduction routes only the old XR module into a test browser, expecting the old Start exception. Repaired acceptance loads the actual candidate or public URL without replacing runtime files. All hardware poses/events are labeled emulation; tests never assign gameplay health, score, actors, clock or completion. The existing two full River chapter playthroughs remain unchanged and are rerun after the UI suite.

Local Node contracts passed 217 tests before native CI. Chromium is not installed in this local container, and external hostname resolution is unavailable; native source/public acceptance runs on GitHub Actions. A native CI result, served-file match and physical Quest confirmation are separate evidence. The final PR and publication receipt must be consulted for actual completion. User-device acceptance remains open until the owner retests.

The combat core, geometry, soundtrack, desktop/Xbox controls, stored-record formats and retained rhythm/water modes are unchanged. The app snapshot only gains the release identifier and read-only XR UI diagnostics. The release entry uses new cache-versioned script URLs. Rollback must revert only this scoped repair on current master, never reset the repository or clear localStorage.

Primary API references are W3C WebXR Device API section 10.3 (XRInputSourceArray), W3C WebXR Gamepads Module xr-standard mapping, and Three.js Raycaster/Object3D documentation. See https://www.w3.org/TR/webxr/#xrinputsourcearray, https://immersive-web.github.io/webxr-gamepads-module/, https://threejs.org/docs/pages/Raycaster.html and https://threejs.org/docs/pages/Object3D.html.
