# Clear Shoals / Currentworks Water Optics 0.2.0

This is the new optical layer on the existing Currentworks Water 0.1.0 surface, not a replacement for its wave geometry, CPU height query, wakes, splashes, or game clock. The normal Prism entry loads it through the existing AR-islands adapter. That adapter also preserves screen and VR river views. Minimal scenery hides the islands, not water or gameplay. See CLEAR-SHOALS-CHECKPOINT.md and the dated result for actual acceptance, not an inferred pass from this source document.

## What changes

A generated pebble texture gives the authored riverbed more shape and contrast. Fine wave normals use an independently seeded periodic spectrum with stored squared-slope information. Mip filtering can then broaden distant highlights instead of treating unresolved ripples as an artificially smooth mirror. This is a scalar roughness approximation, not full anisotropic LEAN mapping.

The caustic atlas is generated by refracting a fixed grid of light rays and accumulating their flux onto a reference bed. Before display clamping, the bake conserves total incident flux; flat normals give uniform light. It is generated once at attachment and subsequently advected with the paused host clock. Depth-dependent weighting and translation are approximate: the atlas is not regenerated from the instantaneous geometric waves or new light direction. The reference depth is 1.25 local units.

The Fresnel helper uses unpolarized air/water dielectric reflectance adapted from Clearwater, with attribution and MIT terms in CLEARWATER-NOTICE.txt. Refracted directions are converted from the current draw's view frame into water-local coordinates using the actual transformed axes. This preserves rotated and nonuniformly narrowed AR placement rather than using a cached mono camera.

Reflection still samples an analytic sky, not a copy of the virtual scene or passthrough room. The bed is procedural, not the real floor. There is no FFT simulation, additional scene render, screen-space refraction, postprocessing bloom, float-target requirement or room-image access. Clearwater's complete standalone pipeline is not imported.

## Reuse

```js
import Water from './water.mjs';
import Optics from './water-optics.mjs';
const water = Water.create(THREE, {preset: 'river', depth: 1.25});
const optics = Optics.attach(THREE, water.material);
scene.add(water.mesh);
// Use the existing host loop and pause-aware time.
water.update({time: simulationTime, level: tide, opacity: savedOpacity,
              quiet: quietMotion, xr: immersive, bodies: localBoatObservations});
optics.update({ar: immersiveAR});
// When permanently removing this surface:
optics.dispose();
water.dispose();
```

Classic scripts load water.js, water-detail.js and water-optics.js in that order, then call SVGNWaterOptics.attach. The ES facade imports its data dependency automatically; Node can require the modules. The caller supplies its existing compatible Three.js instance. Do not create another renderer or timer.

The extension validates its exact Water 0.1.0 shader patch locations before allocating or modifying material state. Attaching twice is rejected. Disposal restores both original shader sources, removes its added uniforms, and disposes only its own two textures, once. Detach optics before disposing base water. A deliberate later attachment is supported. Another extension that edits the same shader sources needs explicit composition; do not assume arbitrary patch order is safe.

Water remains the owner of time, level, opacity and geometric detail. The optics update changes only its AR near-viewer fade flag; it does not advance clocks or write input, collisions, scores, health, difficulty or saves. Quiet mode freezes the shared shader time. Stored settings are not overwritten. Opacity is the per-surface strength, not a global composited-alpha maximum: projected wave overlaps can accumulate, as measured in CLEAR-SHOALS-ALPHA-RESULT.md. Zero opacity removes the water and AR retains its near-viewer fade.

## Resource bounds and limitations

Two generated mipmapped RGBA8 textures are added: 128x128 for slope/moment/focused-light data and 256x256 for bed albedo/relief. Their base levels total 327680 bytes; the complete uncompressed mip chains total 436904 bytes, excluding driver bookkeeping. The normal base-water texture is reused. Ordinary frame updates allocate no textures and upload no new images. No additional render targets or reflected-scene passes are introduced.

Data generation and first GPU use belong before rhythm playback in the host's loading path. These are fixed source budgets, not a claim of measured Quest performance. WebGL context replacement and engine upgrades require renewed validation. The current tests use bundled Three r184 and the pre-existing WebGL2 path.

The procedural bed plane, reference-depth caustics, capped focused-light range, scalar variance filtering and scrolling atlas are approximations. They do not reproduce Clearwater's evolving FFT spectrum, live refracted-grid caustics, interactive fluid field, stochastic high-resolution pebble sampling or diffraction postprocess. Future work should select one meaningful improvement and measure it in AR before adding more passes.
