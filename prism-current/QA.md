# River Prism 0.10.0 verification index

The main playable entry is now index.html, containing Duck Armada and Mothership Channel. The original rhythm experience is retained at rhythm.html. Its previous QA document is archived unchanged at [QA-v090.md](QA-v090.md); it is historical evidence, not the acceptance record for the new main entry.

[RIVER_QA.md](RIVER_QA.md) records the new test scope, observed failures and runtime corrections. [PR #193](https://github.com/v5ma/v5ma.github.io/pull/193) is the source of exact candidate/merge hashes, workflow conclusions, artifact receipts and live-publication status. An implementation checkbox or this procedure is not proof that a workflow passed.

The new native suite exercises two real-time chapter clears through actual input handlers, directional slicing, aimed lasers, oriented shields, pause/resume, legacy save isolation, new record reload, controller mappings/disconnection, tracked XR combat and hand-pinch menu input. No test may set health, position, score, clock, boss damage or completion to manufacture a passing battle. Separate pure-model tests cover those rules as labeled fixtures.

Legacy suites select the retained rhythm entry and its preserved rhythm-release.json. Their original gameplay criteria remain, while the new main entry has separate acceptance. All reported results must distinguish unchanged legacy coverage from exercised River mechanics.

Software-rendered browser tests use reduced gameplay drawing buffers and separate full-resolution visual captures. Physical Quest/Xbox/touch, ordinary-resolution performance, comfort, unfamiliar-player readability and owner music/fun acceptance remain open. Both River chapters currently use the same original Undertow composition.

Public acceptance must compare the committed runtime/documentation hashes against GitHub Pages and rerun the actual main-entry battles. The final receipt must identify failures and retries as well as successful conclusions. Temporary source-transport scripts and write-enabled staging workflows must be absent from the release tree; final verification workflows are read-only.
